# Docker Secrets — Create, Store, and Read (nopCommerce Stack)

Secrets let you keep sensitive values (DB passwords, connection strings, API keys) **out of** your `Dockerfile`, `docker-compose.yml`, and `docker history` — instead of passing them as plain `environment:` values (as in the current nop compose file).

---

## 1. How Docker Secrets Work

| Concept | Detail |
|---|---|
| Storage | Secret value is written to a file, mounted **in-memory** inside the container at `/run/secrets/<secret_name>` |
| Delivery path | **Compose file-based secrets** — works with plain `docker compose`, no Swarm needed |
| Build-time | `docker build --secret` (BuildKit) — value never lands in an image layer |
| Runtime (plain `docker run`) | No native `--secret` flag — emulate with a read-only bind mount to `/run/secrets/<name>` |
| App side | App reads the **file**, not an env var, e.g. `cat /run/secrets/db_password` |

```
 Host file (secrets/mysql_root_password.txt)
        │
        ▼
 compose "secrets:" block
        │
        ▼
 Container: /run/secrets/mysql_root_password   (read-only, tmpfs)
        │
        ▼
 App/entrypoint reads file → uses value
```

---

## 2. Step 1 — Create the Secret Files

```bash
mkdir -p secrets
echo "rootpassword"  > secrets/mysql_root_password.txt
echo "noppassword"   > secrets/mysql_password.txt
chmod 600 secrets/*.txt
```

Add to `.gitignore`:
```
secrets/
```

---

## 3. Step 2 — Secrets in `docker-compose.yml`

Add a top-level `secrets:` block, then reference it per service. This works with `docker compose up` directly — no daemon mode changes required.

```yaml
version: "1.0"
services:
  nop:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: "nop_container"
    command: ["dotnet", "Nop.Web.dll"]
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - DOTNET_PRINT_TELEMETRY_MESSAGE=false
      - ASPNETCORE_URLS=http://+:5000
      - DOTNET_RUNNING_IN_CONTAINER=true
      - nop_version=4.90.8
      - aspnetcore=9.0
      - DOTNET_VERSION=9.0
      - ConnectionStrings__DataProvider=MySql
      - ConnectionStrings__ConnectionString=Server=mysql;Port=3306;Database=nopcommerce;Uid=nopuser;AllowUserVariables=True;
    secrets:
      - mysql_password
    ports:
      - "5000:5000"
    networks:
      - nop-network
    volumes:
      - nop-data:/app
    restart: unless-stopped

  mysql:
    image: "mysql:8.0"
    container_name: "mysql_container"
    environment:
      - MYSQL_DATABASE=nopcommerce
      - MYSQL_USER=nopuser
      - MYSQL_ROOT_PASSWORD_FILE=/run/secrets/mysql_root_password
      - MYSQL_PASSWORD_FILE=/run/secrets/mysql_password
    secrets:
      - mysql_root_password
      - mysql_password
    ports:
      - "3306:3306"
    networks:
      - nop-network
    volumes:
      - mysql-data:/var/lib/mysql
    restart: unless-stopped

volumes:
  mysql-data:
  nop-data:

networks:
  nop-network:
    driver: bridge

secrets:
  mysql_root_password:
    file: ./secrets/mysql_root_password.txt
  mysql_password:
    file: ./secrets/mysql_password.txt
```

Notes on the diff from your original file:
- Removed the duplicate `ASPNETCORE_ENVIRONMENT` key (Development + Production both set — only the last wins).
- `Pwd=` removed from `ConnectionStrings__ConnectionString`; the app must read it from `/run/secrets/mysql_password` instead (Section 5).
- `secrets:` (top-level) declares the source file → secret name mapping.
- `secrets:` (per-service) mounts only the ones each container needs, at `/run/secrets/<name>`.

Bring it up:
```bash
docker compose up -d
docker compose exec nop cat /run/secrets/mysql_password
```

## 4. Reading a Secret in the `Dockerfile` (build-time)

Use for values needed only **during image build** (e.g., pulling a private NuGet feed). Requires BuildKit (default in modern Docker).

```dockerfile
# syntax=docker/dockerfile:1
FROM mcr.microsoft.com/dotnet/sdk:9.0 AS build
WORKDIR /src

RUN --mount=type=secret,id=nuget_token \
    NUGET_TOKEN=$(cat /run/secrets/nuget_token) && \
    dotnet nuget add source https://my-feed/index.json \
      -n private -u user -p "$NUGET_TOKEN" --store-password-in-clear-text

COPY . .
RUN dotnet restore && dotnet publish -c Release -o /app/publish
```

Build with the secret supplied on the CLI (never baked into a layer, never in `docker history`):
```bash
docker build --secret id=nuget_token,src=./secrets/nuget_token.txt -t nop:1.0 .
```

## 5. Reading the Secret Inside the Running Container

The nopCommerce/.NET app needs the password as a **connection string value**, not a raw file — so resolve it in an entrypoint script before `dotnet Nop.Web.dll` starts.

`entrypoint.sh`:
```bash
#!/bin/sh
set -e

if [ -f /run/secrets/mysql_password ]; then
  DB_PWD=$(cat /run/secrets/mysql_password)
  export ConnectionStrings__ConnectionString="Server=mysql;Port=3306;Database=nopcommerce;Uid=nopuser;Pwd=${DB_PWD};AllowUserVariables=True;"
fi

exec dotnet Nop.Web.dll
```

Dockerfile:
```dockerfile
COPY entrypoint.sh /app/entrypoint.sh
RUN chmod +x /app/entrypoint.sh
ENTRYPOINT ["/app/entrypoint.sh"]
```

Compose `command:` is no longer needed once `ENTRYPOINT` handles startup — remove the `command: ["dotnet", "Nop.Web.dll"]` line, or leave it; `ENTRYPOINT` takes precedence and `exec` inside the script replaces the shell process.

## 6. Reading a Secret with plain `docker run` (no Compose)

There's no native `--secret` flag for standalone `docker run`. Emulate the same `/run/secrets/<name>` convention with a read-only bind mount:

```bash
docker run -d \
  -p 5000:5000 \
  -v $(pwd)/secrets/mysql_password.txt:/run/secrets/mysql_password:ro \
  -e ConnectionStrings__DataProvider=MySql \
  --name nop_container \
  nop:1.0
```

The `entrypoint.sh` from Section 5 reads the file the same way regardless of how it got mounted.

## 7. Command Cheat Sheet

| Task | Command |
|---|---|
| Build with secret | `docker build --secret id=<id>,src=<file> .` |
| Compose up (file-based secrets) | `docker compose up -d` |
| Verify inside container | `docker compose exec <service> cat /run/secrets/<name>` |
| Run with mounted secret | `docker run -v <file>:/run/secrets/<name>:ro ...` |

---

## 8. Key Rules to Remember

- Secrets are **files**, not environment variables — never `echo $SECRET`; always read the file path.
- `docker compose up` uses the `secrets:` block directly — no Swarm mode, no daemon changes required.
- `docker build --secret` keeps the value out of image layers and `docker history`; a plain `ARG`/`ENV` with a password does **not**.
- Never commit the `secrets/` folder — add it to `.gitignore`.
- The official `mysql` image supports `*_FILE` env vars (`MYSQL_ROOT_PASSWORD_FILE`, `MYSQL_PASSWORD_FILE`) that read secrets automatically — no entrypoint script needed on the MySQL side.
