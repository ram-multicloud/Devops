# Docker Compose — Complete Guide

## What is Docker Compose?

Docker Compose is a tool for defining and running **multi-container Docker applications**. Instead of starting each container manually with long `docker run` commands, you describe all your services (app, database, cache, etc.) in a single YAML file called `docker-compose.yml`, and then start everything with one command.

**Key benefits:**
- Define your entire application stack (app + database + cache + etc.) in one file
- Start/stop all services together with a single command
- Automatic networking between containers (services can reach each other by name)
- Easy to version control your infrastructure setup
- Great for local development, testing, and simple production setups

**How it works:**
1. You write a `docker-compose.yml` file describing each service (image, ports, volumes, environment variables, dependencies).
2. Compose reads the file and creates a private network for your app.
3. Each service runs in its own container, but they can talk to each other using the service name as the hostname (e.g., a `web` service can reach `db:3306`).

## Installing Docker Compose

Docker Compose comes in two flavors:
- **Compose V2** (current, recommended) — built into Docker Desktop and the `docker` CLI as `docker compose` (no hyphen)
- **Compose V1** (legacy) — separate binary invoked as `docker-compose`

This guide uses the modern `docker compose` syntax.

### Windows / macOS
Docker Compose is included automatically when you install **Docker Desktop**.
1. Download Docker Desktop from https://www.docker.com/products/docker-desktop
2. Install and launch it
3. Verify:
   ```bash
   docker compose version
   ```

### Linux
Docker Compose V2 ships as a plugin with Docker Engine on most modern installs.

**Ubuntu/Debian example:**
```bash
# Install Docker Engine (if not already installed)
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg -y

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io docker-compose-plugin -y

# Verify installation
docker compose version
```

**If you only need the standalone binary (older systems):**
```bash
sudo curl -L "https://github.com/docker/compose/releases/latest/download/docker-compose-$(uname -s)-$(uname -m)" -o /usr/local/bin/docker-compose
sudo chmod +x /usr/local/bin/docker-compose
docker-compose --version
```

## Basic Compose Commands

| Command | Description |
|---|---|
| `docker compose up` | Create and start all services |
| `docker compose up -d` | Start in detached (background) mode |
| `docker compose down` | Stop and remove containers, networks |
| `docker compose down -v` | Also remove volumes (deletes data!) |
| `docker compose ps` | List running services |
| `docker compose logs` | View logs from all services |
| `docker compose logs -f web` | Follow logs for a specific service |
| `docker compose build` | Build/rebuild images |
| `docker compose restart` | Restart all services |
| `docker compose exec web bash` | Open a shell inside the `web` container |
| `docker compose stop` | Stop services without removing them |

## Anatomy of a `docker-compose.yml` File

```yaml
services:
  service_name:          # name of your service (e.g. web, db, redis)
    image: some_image     # use a pre-built image...
    build: .               # ...OR build from a local Dockerfile
    ports:
      - "host_port:container_port"
    environment:
      - KEY=value
    volumes:
      - host_path:container_path
    depends_on:
      - other_service
    networks:
      - my_network

volumes:
  my_volume:

networks:
  my_network:
```

## Example 1: Node.js App + MySQL

**Project structure:**
```
myapp/
├── docker-compose.yml
├── Dockerfile
├── package.json
└── index.js
```

**Dockerfile** (for the Node app):
```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "index.js"]
```

**docker-compose.yml:**
```yaml
services:
  app:
    build: .
    container_name: node_app
    ports:
      - "3000:3000"
    environment:
      - DB_HOST=db
      - DB_USER=root
      - DB_PASSWORD=rootpassword
      - DB_NAME=myappdb
    depends_on:
      - db
    networks:
      - app_network

  db:
    image: mysql:8.0
    container_name: mysql_db
    restart: always
    environment:
      - MYSQL_ROOT_PASSWORD=rootpassword
      - MYSQL_DATABASE=myappdb
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    networks:
      - app_network

volumes:
  mysql_data:

networks:
  app_network:
```

Inside the Node app, you'd connect to MySQL using the **service name** `db` as the host (not `localhost`):
```js
const connection = mysql.createConnection({
  host: 'db',
  user: 'root',
  password: 'rootpassword',
  database: 'myappdb'
});
```

Run it:
```bash
docker compose up -d
```

## Example 2: WordPress + MySQL

A classic pairing — WordPress needs a MySQL/MariaDB database.

```yaml
services:
  wordpress:
    image: wordpress:latest
    container_name: wordpress_site
    ports:
      - "8080:80"
    environment:
      - WORDPRESS_DB_HOST=db
      - WORDPRESS_DB_USER=wpuser
      - WORDPRESS_DB_PASSWORD=wppassword
      - WORDPRESS_DB_NAME=wordpress
    depends_on:
      - db
    volumes:
      - wordpress_data:/var/www/html

  db:
    image: mysql:8.0
    container_name: wordpress_db
    restart: always
    environment:
      - MYSQL_DATABASE=wordpress
      - MYSQL_USER=wpuser
      - MYSQL_PASSWORD=wppassword
      - MYSQL_ROOT_PASSWORD=rootpassword
    volumes:
      - db_data:/var/lib/mysql

volumes:
  wordpress_data:
  db_data:
```

Visit `http://localhost:8080` after running `docker compose up -d`.

## Example 3: Python (Flask) + PostgreSQL + Redis

Shows a slightly more complex stack with three services.

```yaml
services:
  web:
    build: .
    ports:
      - "5000:5000"
    environment:
      - DATABASE_URL=postgresql://postgres:postgres@db:5432/flaskdb
      - REDIS_URL=redis://cache:6379
    depends_on:
      - db
      - cache

  db:
    image: postgres:16
    restart: always
    environment:
      - POSTGRES_USER=postgres
      - POSTGRES_PASSWORD=postgres
      - POSTGRES_DB=flaskdb
    volumes:
      - pg_data:/var/lib/postgresql/data

  cache:
    image: redis:7-alpine
    restart: always

volumes:
  pg_data:
```

## Tips & Best Practices

1. **Never hardcode secrets** in `docker-compose.yml` for production — use a `.env` file or Docker secrets.
2. Use `depends_on` for startup order, but note it doesn't wait for the service to be *ready* (e.g., MySQL accepting connections) — for that, use healthchecks:
   ```yaml
   healthcheck:
     test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
     interval: 10s
     timeout: 5s
     retries: 5
   ```
3. Use **named volumes** (like `mysql_data:`) instead of bind mounts for databases, so data persists properly.
4. Use `.env` files to store variables and reference them with `${VARIABLE_NAME}` in the compose file.
5. Run `docker compose config` to validate and preview your merged configuration.
6. Use `docker compose down -v` carefully — it deletes volumes (and your data) permanently.

## Quick Start Checklist

1. Install Docker Desktop (Win/Mac) or Docker Engine + Compose plugin (Linux)
2. Create a project folder with `docker-compose.yml`
3. Define your services (app, database, cache, etc.)
4. Run `docker compose up -d`
5. Check status with `docker compose ps`
6. View logs with `docker compose logs -f`
7. Stop with `docker compose down`
