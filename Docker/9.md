# nopCommerce on Docker (Ubuntu base) — Full Setup

Based on: https://docs.nopcommerce.com/en/installation-and-upgrading/installing-nopcommerce/installing-on-linux.html

Two containers: `nopcommerce_app` (the app) and `nopcommerce_mysql` (the database),
connected over a shared Docker network. No nginx — the app is accessed directly on port 5000.

## 1. Dockerfile

Save as `Dockerfile`:

```dockerfile
FROM ubuntu

ENV DEBIAN_FRONTEND=noninteractive \
    ASPNETCORE_ENVIRONMENT=Production \
    DOTNET_PRINT_TELEMETRY_MESSAGE=false \
    NOPCOMMERCE_VERSION=4.90.8

# --- Add the .NET repository & install the ASP.NET Core Runtime ---
RUN apt-get update && \
    apt-get install -y --no-install-recommends software-properties-common wget unzip ca-certificates gnupg && \
    add-apt-repository ppa:dotnet/backports && \
    apt-get update && \
    apt-get install -y --no-install-recommends aspnetcore-runtime-9.0 libgdiplus && \
    rm -rf /var/lib/apt/lists/*

# --- Get nopCommerce ---
WORKDIR /var/www/nopCommerce

RUN wget -q https://github.com/nopSolutions/nopCommerce/releases/download/release-${NOPCOMMERCE_VERSION}/nopCommerce_${NOPCOMMERCE_VERSION}_NoSource_linux_x64.zip && \
    unzip -q nopCommerce_${NOPCOMMERCE_VERSION}_NoSource_linux_x64.zip && \
    rm nopCommerce_${NOPCOMMERCE_VERSION}_NoSource_linux_x64.zip && \
    mkdir -p bin logs

# --- Permissions ---
RUN chgrp -R www-data /var/www/nopCommerce && \
    chown -R www-data /var/www/nopCommerce

USER www-data

EXPOSE 5000

# Replaces the systemd nopCommerce.service from the guide
ENTRYPOINT ["dotnet", "/var/www/nopCommerce/Nop.Web.dll"]
```

## 2. Build the app image

```bash
docker build -t nopcommerce-app .
```

## 3. Create a shared network

```bash
docker network create nopnet
```

## 4. Run MySQL

```bash
docker run -d \
  --name nopcommerce_mysql \
  --network nopnet \
  -e MYSQL_ROOT_PASSWORD=ChangeMe_StrongPassword123! \
  -e MYSQL_DATABASE=nopcommerce \
  mysql:8.0
```

## 5. Run the nopCommerce app

```bash
docker run -d \
  --name nopcommerce_app \
  --network nopnet \
  -p 5000:5000 \
  -e ASPNETCORE_URLS=http://+:5000 \
  nopcommerce-app
```

## 6. Verify both containers are up

```bash
docker ps
docker logs -f nopcommerce_app
```

## 7. Open the install wizard

Browse to:

```
http://localhost:5000
```

(or `http://<server-ip>:5000` if running on a remote host)

## 8. Database connection details for the install wizard

| Field | Value |
|---|---|
| Server name | `nopcommerce_mysql` |
| Port | `3306` |
| User name | `root` |
| Password | `ChangeMe_StrongPassword123!` (whatever you set in Step 4) |
| Database name | `nopcommerce` |

Raw connection string equivalent (if a field asks for it):

```
Server=nopcommerce_mysql;Port=3306;Database=nopcommerce;Uid=root;Pwd=ChangeMe_StrongPassword123!;
```

> Using `root` works for local/testing setups. For anything beyond that, create a
> dedicated MySQL user scoped to the `nopcommerce` database instead of using root.

## Useful commands

```bash
# Stop both containers
docker stop nopcommerce_app nopcommerce_mysql

# Start them again
docker start nopcommerce_mysql
docker start nopcommerce_app

# Remove everything (containers + network) to start fresh
docker rm -f nopcommerce_app nopcommerce_mysql
docker network rm nopnet

# Rebuild app image after Dockerfile changes
docker build -t nopcommerce-app .
docker rm -f nopcommerce_app
docker run -d --name nopcommerce_app --network nopnet -p 5000:5000 \
  -e ASPNETCORE_URLS=http://+:5000 nopcommerce-app
```

## Troubleshooting

| Issue | Fix |
|---|---|
| Browser can't reach `http://localhost:5000` | Check `docker ps` for `0.0.0.0:5000->5000/tcp`; check cloud firewall/security group if remote |
| App container restarting | `docker logs nopcommerce_app` — often means MySQL wasn't ready yet on first boot; wait a few seconds and retry |
| Install wizard fails at DB step | Confirm server name is `nopcommerce_mysql` (container name), not `localhost` |
| `Gdip` image-loading error | Already handled — `libgdiplus` is installed in the Dockerfile |
