# Docker Components

Installing Docker brings three core pieces:

- **Docker client** — the command-line application used to issue commands
- **Docker daemon** — the background service that does the actual work
- **Local storage** — where images and related data live

Docker can be installed on Windows, Linux, and Mac.

## Play with Docker

- Use the [Play with Docker](https://labs.play-with-docker.com/) playground to practice without a local install.
- A [Docker Hub account](https://hub.docker.com/) is required to use it.
- The playground provisions a Linux machine with Docker already installed.

### Getting Comfortable with the CLI

- `docker info` shows details about both the **client** and the **server**.
- Running a container requires an **image**.
- Docker Hub acts as a **registry** — a collection of **repositories**, where each repository corresponds to one image (an application or OS).
- **Tags** are used to manage different versions of an image.

**Docker Hub naming conventions:**
- Official images: `<image-name>:<tag>`
- Other images: `<account>/<image-name>:<tag>`
- If no tag is specified, Docker uses a default tag.

An image must exist locally before a container can be run from it. To list local images:

```bash
docker images
docker image ls
```

To run something like Nginx in a container, the image must first be pulled locally.

Reference: [Docker CLI Cheat Sheet (PDF)](https://docs.docker.com/get-started/docker_cheatsheet.pdf)
