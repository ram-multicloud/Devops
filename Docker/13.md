
## 1. Single-Stage Dockerfile (Ubuntu base)

Everything happens in one image: OS setup, .NET runtime install, and app download.

```dockerfile
FROM ubuntu:latest

ENV ASPNETCORE_ENVIRONMENT=Production
ENV DOTNET_PRINT_TELEMETRY_MESSAGE=false
ENV ASPNETCORE_URLS=http://+:5000
ENV DOTNET_RUNNING_IN_CONTAINER=true
ENV nop_version=4.90.8

RUN apt-get update && \
    apt-get install -y --no-install-recommends software-properties-common wget unzip ca-certificates gnupg && \
    add-apt-repository ppa:dotnet/backports && \
    apt-get update && \
    apt-get install -y --no-install-recommends aspnetcore-runtime-9.0 libgdiplus && \
    rm -rf /var/lib/apt/lists/*

RUN mkdir -p /var/www/nopCommerce

WORKDIR /var/www/nopCommerce

RUN wget https://github.com/nopSolutions/nopCommerce/releases/download/release-${nop_version}/nopCommerce_${nop_version}_NoSource_linux_x64.zip

RUN unzip nopCommerce_${nop_version}_NoSource_linux_x64.zip && rm nopCommerce_${nop_version}_NoSource_linux_x64.zip

RUN mkdir bin logs

RUN chown -R www-data:www-data /var/www/nopCommerce

USER www-data

EXPOSE 5000

CMD ["dotnet", "Nop.Web.dll"]
```

**Build & run:**

```bash
docker build -t nopcommerce:single-stage .
docker run -d -p 5000:5000 --name nopcommerce nopcommerce:single-stage
```

**Downside:** the final image carries `wget`, `unzip`, `software-properties-common`, `gnupg`, and other install-time tooling it doesn't need at runtime — larger image size.

## 2. Multi-Stage Dockerfile

Stage 1 downloads/unpacks the release (throwaway build environment). Stage 2 copies only the published app onto a lean ASP.NET runtime image.

```dockerfile
# ---------- Stage 1: Fetch nopCommerce (throwaway) ----------
FROM ubuntu:latest AS fetch

ENV nop_version=4.90.8

RUN apt-get update && \
    apt-get install -y --no-install-recommends wget unzip ca-certificates && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /src

RUN wget https://github.com/nopSolutions/nopCommerce/releases/download/release-${nop_version}/nopCommerce_${nop_version}_NoSource_linux_x64.zip \
    && unzip nopCommerce_${nop_version}_NoSource_linux_x64.zip -d /src/app \
    && rm nopCommerce_${nop_version}_NoSource_linux_x64.zip

# ---------- Stage 2: Runtime image ----------
FROM ubuntu:latest

ENV ASPNETCORE_ENVIRONMENT=Production
ENV DOTNET_PRINT_TELEMETRY_MESSAGE=false
ENV ASPNETCORE_URLS=http://+:5000
ENV DOTNET_RUNNING_IN_CONTAINER=true

RUN apt-get update && \
    apt-get install -y --no-install-recommends software-properties-common ca-certificates gnupg && \
    add-apt-repository ppa:dotnet/backports && \
    apt-get update && \
    apt-get install -y --no-install-recommends aspnetcore-runtime-9.0 libgdiplus && \
    rm -rf /var/lib/apt/lists/*

RUN mkdir -p /var/www/nopCommerce

WORKDIR /var/www/nopCommerce

# Copy only the fetched app from stage 1 — no wget/unzip in the final image
COPY --from=fetch /src/app ./

RUN mkdir -p bin logs && \
    chown -R www-data:www-data /var/www/nopCommerce

USER www-data

EXPOSE 5000

CMD ["dotnet", "Nop.Web.dll"]
```

**Build & run:**

```bash
docker build -t nopcommerce:multi-stage .
docker run -d -p 5000:5000 --name nopcommerce nopcommerce:multi-stage
```

**Benefit:** `wget` and `unzip` (stage 1 only) never make it into the final image — the runtime stage only installs what's needed to actually run nopCommerce.

---

## Notes

- Both examples assume MySQL and nginx run separately (as containers, a docker-compose stack, or external services) — the original install guide sets these up on the host, not inside the app container.
- `nop_version` is set as an env var so it's easy to bump to a newer release.
- `libgdiplus` is included to avoid the `Gdip` image-loading error noted in the original install guide.
- Running as `www-data` instead of root matches the file-permission steps in the original install guide.
