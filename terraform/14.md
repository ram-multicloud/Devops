# Terraform: `refresh`, `graph`, and Type/Fallback Functions

## `terraform refresh`

Reconciles Terraform's state file with the **real** infrastructure — it checks what actually exists in the cloud provider and updates `terraform.tfstate` to match, without changing any real resources.

**Example:** Someone manually resized an EC2 instance in the AWS console (outside Terraform) from `t3.micro` to `t3.large`. Your state file still thinks it's `t3.micro`.

```bash
terraform refresh
```

This updates the state file to record `t3.large` as the current instance type — but it does **not** touch the actual instance. It just fixes Terraform's "memory" of reality.

> Note: `terraform plan` and `apply` do this automatically now, so running `refresh` standalone is rare in modern Terraform — mostly used for inspecting drift.

## `terraform graph`

Outputs the dependency graph (in DOT format) showing the order Terraform will create/modify/destroy resources in.

**Example:**

```bash
terraform graph | dot -Tsvg > graph.svg
```

Given:

```hcl
resource "aws_vpc" "main" { ... }

resource "aws_subnet" "sub" {
  vpc_id = aws_vpc.main.id   # depends on the VPC
}
```

The graph visually shows `aws_subnet.sub → aws_vpc.main`, meaning the VPC must be created first. Useful for debugging "why is X being created after Y" issues.

## Type Conversion Functions

Terraform is normally good at inferring types, but sometimes you need to force a value into a specific type — especially when passing variables between modules or working with dynamic/unknown data.

### `tostring()`

```hcl
tostring(5)     # -> "5"
tostring(true)  # -> "true"
```

Example use: an API returns a number, but a tag value must be a string.

```hcl
tags = {
  port = tostring(var.port)   # var.port = 8080 -> "8080"
}
```

### `tonumber()`

```hcl
tonumber("5")   # -> 5
```

Example: a variable comes in as a string from a `.tfvars` file, but you need to do math with it.

```hcl
variable "instance_count_str" {
  default = "3"
}

count = tonumber(var.instance_count_str)   # "3" -> 3, usable in count
```

### `tolist()`

```hcl
tolist(["a", "b", "c"])   # ensures it's treated as a list (ordered)
```

Example: converting a `set` (unordered) to a `list` (ordered) so you can index into it.

```hcl
locals {
  my_set  = toset(["b", "a", "c"])
  as_list = tolist(local.my_set)
}

output "first" {
  value = local.as_list[0]   # sets can't be indexed directly, lists can
}
```

### `tomap()`

```hcl
tomap({ a = 1, b = 2 })
```

Example: ensuring consistent typing when merging objects that could be interpreted differently.

```hcl
locals {
  settings = tomap({
    env    = "prod"
    region = "us-east-1"
  })
}
```

### `toset()`

```hcl
toset(["a", "b", "a"])   # -> {"a", "b"}  (duplicates removed, unordered)
```

Example: `for_each` requires a **set** or **map**, not a list — so lists often get converted:

```hcl
variable "subnet_names" {
  default = ["web", "app", "db"]
}

resource "aws_subnet" "this" {
  for_each = toset(var.subnet_names)   # list -> set, required for for_each
  # each.key = "web", "app", "db"
  ...
}
```

## Fallback / Error-Handling Functions

### `try()`

Attempts to evaluate an expression; if it errors, falls back to the next value instead of crashing the plan.

```hcl
try(var.x, "fallback")
```

**Example:** Safely accessing an optional nested attribute that might not exist.

```hcl
variable "config" {
  default = {
    name = "app1"
    # "port" key is missing
  }
}

output "port" {
  value = try(var.config.port, 8080)   # falls back to 8080 since "port" doesn't exist
}
```

You can chain multiple fallbacks:

```hcl
value = try(var.config.port, var.default_port, 8080)
```

### `can()`

Returns `true`/`false` depending on whether an expression would succeed — useful inside validation blocks.

```hcl
can(var.x)
```

**Example:** Validating that a variable is a valid CIDR block.

```hcl
variable "cidr" {
  type = string
  validation {
    condition     = can(cidrhost(var.cidr, 0))
    error_message = "Must be a valid CIDR block."
  }
}
```

- If `var.cidr = "10.0.0.0/16"` → `can()` returns `true`.
- If `var.cidr = "not-a-cidr"` → `cidrhost()` would error, so `can()` catches it and returns `false`.

### `coalesce()`

Returns the **first non-null, non-empty** value from a list of arguments.

```hcl
coalesce(var.a, var.b, "default")
```

**Example:** Picking the first available value across an override chain.

```hcl
variable "custom_name" {
  default = null
}

variable "team_name" {
  default = ""
}

locals {
  # skips null and skips "" (empty string), picks first real value
  name = coalesce(var.custom_name, var.team_name, "default-app-name")
}
# result: "default-app-name" if custom_name is null and team_name is ""
```

> **Key distinction:** `coalesce` skips `null` and `""` — it won't skip `false` or `0`, since those are valid non-empty values.
