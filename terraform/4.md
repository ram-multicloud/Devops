# Terraform File Structure and Variables

## 1. Typical Terraform Project Structure

A standard Terraform project is organized into multiple `.tf` files, each with a specific responsibility. Terraform loads and merges **all** `.tf` files in a directory automatically — the split is for readability, not function.

```
project/
├── main.tf              # Primary resource definitions
├── variables.tf         # Input variable declarations
├── outputs.tf           # Output value declarations
├── providers.tf         # Provider configuration
├── terraform.tf         # Terraform settings & required providers/version
├── terraform.tfvars     # Variable value assignments
├── backend.tf           # Remote state backend configuration
└── modules/
    └── vpc/
        ├── main.tf
        ├── variables.tf
        └── outputs.tf
```

### File Purposes

| File | Purpose |
|---|---|
| `main.tf` | Core resource and data source blocks |
| `variables.tf` | Declares input variables (name, type, description, default) |
| `outputs.tf` | Declares values to expose after `apply` |
| `providers.tf` | Configures providers (AWS, Azure, etc.) and their settings |
| `terraform.tf` | `terraform {}` block — required_version, required_providers, backend |
| `terraform.tfvars` | Actual values assigned to declared variables |
| `backend.tf` | Where state is stored (S3, Azure Storage, Terraform Cloud, etc.) |

> Naming convention: file names are not enforced by Terraform (except `terraform.tfvars`). `main.tf`, `variables.tf`, `outputs.tf` are community convention, not a hard requirement.

## 2. Variable Types in Terraform

Terraform supports the following variable types:

| Type | Description | Example |
|---|---|---|
| `string` | A sequence of characters | `"us-east-1"` |
| `number` | Numeric value (integer or float) | `3`, `2.5` |
| `bool` | Boolean value | `true`, `false` |
| `list(type)` | Ordered collection of values of the same type | `["a", "b", "c"]` |
| `set(type)` | Unordered collection of unique values | `["a", "b"]` |
| `map(type)` | Key-value pairs, all values same type | `{env = "dev"}` |
| `object({...})` | Structured type with named attributes, each with its own type | `{name = string, age = number}` |
| `tuple([...])` | Fixed-length sequence where each element can have a different type | `[string, number, bool]` |
| `any` | No type constraint (Terraform infers the type) | — |

## 3. Defining Variables

Variables are declared in `variables.tf` using the `variable` block.

### Basic Syntax

```hcl
variable "<NAME>" {
  type        = <TYPE>
  description = "<DESCRIPTION>"
  default     = <DEFAULT_VALUE>
}
```

### Examples by Type

**String**
```hcl
variable "region" {
  type        = string
  description = "AWS region to deploy resources"
  default     = "us-east-1"
}
```

**Number**
```hcl
variable "instance_count" {
  type        = number
  description = "Number of EC2 instances to create"
  default     = 2
}
```

**Bool**
```hcl
variable "enable_monitoring" {
  type        = bool
  description = "Enable detailed monitoring"
  default     = false
}
```

**List**
```hcl
variable "availability_zones" {
  type        = list(string)
  description = "List of AZs to use"
  default     = ["us-east-1a", "us-east-1b"]
}
```

**Map**
```hcl
variable "instance_tags" {
  type        = map(string)
  description = "Tags to apply to instances"
  default = {
    Environment = "dev"
    Owner       = "devops-team"
  }
}
```

**Object**
```hcl
variable "server_config" {
  type = object({
    name     = string
    cpu      = number
    ha       = bool
  })
  default = {
    name = "web-server"
    cpu  = 2
    ha   = true
  }
}
```

**Tuple**
```hcl
variable "mixed_values" {
  type    = tuple([string, number, bool])
  default = ["app", 8080, true]
}
```

## 4. Assigning Values to Variables

Values can be supplied in several ways, in order of precedence (highest wins):

1. Command-line flag: `terraform apply -var="region=us-west-2"`
2. Variable definitions file: `-var-file="prod.tfvars"`
3. `terraform.tfvars` or `*.auto.tfvars` (auto-loaded)
4. Environment variables: `TF_VAR_region=us-west-2`
5. `default` value inside the `variable` block

### terraform.tfvars Example
```hcl
region             = "us-east-1"
instance_count     = 3
enable_monitoring  = true
availability_zones = ["us-east-1a", "us-east-1b"]
```

## 5. Referencing Variables

Variables are referenced elsewhere in the configuration using `var.<NAME>`.

```hcl
resource "aws_instance" "web" {
  ami           = "ami-0abcd1234"
  instance_type = "t2.micro"
  count         = var.instance_count

  tags = var.instance_tags
}
```
