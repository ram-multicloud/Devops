# Using Terraform Modules from Private GitHub Repositories with a PAT

When working with Terraform, you often need to source modules hosted in private GitHub repositories. To allow Terraform to authenticate and download these modules, you can use a GitHub Personal Access Token (PAT).

## Prerequisite: Generate a GitHub PAT
1. Go to your GitHub Settings > **Developer settings** > **Personal access tokens**.
2. Generate a new token (Classic or Fine-grained).
3. Ensure it has at least the **`repo`** scope (Full control of private repositories) so it can pull the module code.

---

## Method 1: Git Configuration (Recommended & Best for CI/CD)

The most secure and seamless way to authenticate is by telling Git to automatically inject your PAT whenever Terraform tries to reach `github.com`. Terraform relies on Git under the hood to download modules.

Run this command in your terminal or add it as a step in your CI/CD pipeline (like GitHub Actions) before running `terraform init`:

```bash
git config --global url."https://oauth2:<YOUR_GITHUB_PAT>@github.com".insteadOf "https://github.com"
```

In your Terraform code, keep the module source completely clean of any secrets. Terraform will use standard HTTPS, and Git will handle the authentication seamlessly:

```hcl
module "my_private_module" {
  source = "git::https://github.com/my-org/my-private-repo.git//path/to/module?ref=v1.0.0"
  
  # Module variables...
}
```

---

## Method 2: The `.netrc` File (Great for Local Development)

If you are working locally and don't want to alter your global Git config URLs, you can store your GitHub credentials in a hidden network runtime configuration file.

### 1. Create or edit the `.netrc` file
Create or edit `~/.netrc` (Linux/macOS) or `_netrc` (Windows) in your home directory and add your GitHub details:

```text
machine github.com
login oauth2
password <YOUR_GITHUB_PAT>
```
*(Note: You can use `oauth2`, `x-access-token`, or your actual GitHub username as the login).*

### 2. Secure the file
Ensure the file has strict permissions so other users cannot read it:

```bash
chmod 600 ~/.netrc
```

### 3. Terraform Module Block
Your Terraform code remains clean, just like in Method 1:

```hcl
module "my_private_module" {
  source = "git::https://github.com/my-org/my-private-repo.git"
}
```

---

## Method 3: Inline Source URL (Not Recommended)

You can pass the PAT directly in the `source` argument of the Terraform module. 

**⚠️ Warning:** This method is heavily discouraged. Terraform module `source` addresses must be literal strings (you cannot interpolate variables). This means your PAT will be exposed in plain text in your code and potentially committed to version control.

```hcl
module "my_private_module" {
  # Format: git::https://<USERNAME>:<PAT>@github.com/<ORG>/<REPO>.git
  
  source = "git::https://oauth2:ghp_12345EXAMPLE_TOKEN890@github.com/my-org/my-private-repo.git"
}
```
